How to Create a Reusable Active Link Component in Next.js App Router

March 2024 5 min read Next.js · TypeScript · Frontend

Providing a seamless navigation experience is crucial for building engaging web applications. One way to achieve this is by implementing an active link component that visually highlights the current page — helping users effortlessly track their location. In this tutorial, we'll build a reusable ActiveLink component for Next.js App Router using usePathname, clsx, and tailwind-merge.

prerequisites

Prerequisites

Before we begin, you'll need a basic understanding of Next.js and React, plus Node.js installed on your machine.

"Basic understanding" is doing a lot of work here. If you've never touched Next.js before, that's fine — but this tutorial won't stop to explain what a component is.

getting started

Getting Started

Step 1: Create a New Next.js Project

Create a new project, navigate into it, then install the two dependencies we'll need:

bash 
npx create-next-app@latest nextjs-active-link
bash 
cd nextjs-active-link
bash 
npm install tailwind-merge clsx
💡 Tip

clsx handles conditional class merging. tailwind-merge resolves Tailwind class conflicts so overrides actually override. Together they're the standard pairing for dynamic class logic in Tailwind projects — you'll see this duo in most production Next.js codebases.

Step 2: Set Up the Components Folder

Create a components/ folder inside src/ and add a file named active-link.tsx. Also create a utils/ folder with a cn.ts file for the class name utility.

Yes, a folder and a file inside it. Groundbreaking — but getting the structure right now saves the "where does this live?" conversation during code review.

Step 3: Implement the Classnames Utility

The cn function wraps both libraries into a single import. Any component that needs conditional classes will use this instead of manual string concatenation:

ts 
import { type ClassValue, clsx } from 'clsx';
import { twMerge } from 'tailwind-merge';

export function cn(...inputs: ClassValue[]) {
	return twMerge(clsx(inputs));
}
❌ Manual concatenation
`className={\`link \${isActive ? 'active' : ''}\`}`
Breaks on Tailwind conflicts
Hard to compose multiple conditions
✅ cn() utility
`className={cn('link', isActive && 'active')}`
Merges Tailwind classes safely
Composes cleanly across any number of conditions

Step 4: Develop the Active Link Component

The component wraps Next.js's built-in Link, reads the current path via usePathname, and conditionally applies activeClassName when the route matches:

tsx 
'use client';

import Link from 'next/link';
import { usePathname } from 'next/navigation';

import { cn } from '~/utils/cn';

interface Props extends React.ComponentPropsWithoutRef<typeof Link> {
	className?: string;
	activeClassName?: string;
}

export const ActiveLink = (props: Props) => {
	const pathname = usePathname();
	const isActive = pathname === props.href;
	const activeClassName = props.activeClassName ?? 'text-red-500';

	return <Link {...props} className={cn(props.className, isActive && activeClassName)} />;
};

"The magic isn't in the component itself — it's that usePathname makes active state automatic. No prop-passing, no context, no global state. Just the URL."

The 'use client' directive is required because usePathname is a client-side hook. The rest of your layout can stay server-rendered — only this component needs to hydrate on the client.

⚠️ Warning

If you forget 'use client', Next.js throws at runtime, not at build time. The error message is clear enough, but it's the kind of thing you only want to learn once.

Step 5: Integrate Active Link in the Layout

Import ActiveLink into your root layout and use it like any other Link — but with an extra activeClassName prop for the highlighted state:

tsx 
import type { Metadata } from 'next';
import { Inter } from 'next/font/google';
import './globals.css';

import { ActiveLink } from '~/components/active-link'; // Import the ActiveLink component

const inter = Inter({ subsets: ['latin'] });

export const metadata: Metadata = {
	title: 'Create Next App',
	description: 'Generated by create next app'
};

export default function RootLayout({
	children
}: Readonly<{
	children: React.ReactNode;
}>) {
	return (
		<html lang="en">
			<body className={inter.className}>
				<nav className="container mx-auto flex items-center justify-center gap-10 py-10">
					{/* Use the ActiveLink component */}
					{[...Array(10)].map((_, i) => (
						<ActiveLink key={i} href={`/${i}`} className="px-2 py-1" activeClassName="bg-blue-500 !text-white">
							Link {i}
						</ActiveLink>
					))}
				</nav>
				{children}
			</body>
		</html>
	);
}

When the current path matches href, activeClassName merges in alongside className. In this example, the active link gets a blue background and white text — swap in whatever your design system calls for.

✓ Verdict

Three files, one hook, zero state management. The ActiveLink component is self-contained, type-safe, and composable across any layout — exactly what a utility component should be.

conclusion

Conclusion

Active link highlighting is a small UX detail with a disproportionate impact on how navigable your app feels. Users shouldn't need to glance at the URL bar to know where they are — the nav should tell them.

With usePathname handling path-matching and cn() managing the class logic, this component stays under 15 lines and handles every edge case cleanly. Extend it as needed: prefix matching, disabled states, mobile-specific active styles.

"The best UI components are the ones you stop thinking about. Build them right once, and they disappear into the background — letting users focus on your content instead of your chrome."
