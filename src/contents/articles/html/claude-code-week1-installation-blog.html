Claude Code Week 1: Installation, Commands & First Workflow

May 2026 8 min read Installation · First Commands · Real Talk

After months of using Claude in the browser—asking questions, generating code snippets, reviewing pull requests—I finally installed Claude Code, the terminal-based coding assistant. I spent a week exploring what it actually does, and here's the unvarnished version of what I found.

the switch

Why I Made the Switch

The repetitive cycle of copying code from a chat window to my editor, pasting error messages back, and re-explaining relevant files was becoming tedious. Claude Code, people kept saying, is fundamentally different—it operates more like a junior developer that can directly access and modify your codebase.

The copy-paste loop gets old fast. Especially when Claude needs context from five different files and you're playing carrier pigeon between two windows.

⚡ Prerequisites

Ensure you have Node.js 18 or higher installed. Verify with node --version. A Claude account is required — the Pro plan is recommended, as Claude Code can consume many tokens during an active session.

installation

Installation — Easier Than Anticipated

I expected a complicated setup involving multiple configuration files, environment variables, and possibly a Docker container. I was wrong.

Step 1 — Install via npm

bash
npm install -g @anthropic-ai/claude-code

Step 2 — Authenticate

Navigate to your project folder and run claude. On first run, a browser window opens to connect your Anthropic account. Takes less than a minute.

terminal
cd my-project
claude
# Opens browser auth flow on first run
✓  Logged in as you@example.com
✓  Welcome to Claude Code
>

Step 3 (Optional) — VS Code Extension

The VS Code extension integrates Claude Code directly into the sidebar. Search "Claude Code" in the marketplace. I use both: terminal for long sessions, the panel for quick questions while reviewing code.

That's it. No Docker. No YAML. No three-hour Stack Overflow spiral. I stared at the terminal for a moment genuinely expecting something to go wrong.

✓ Verdict

No .env file, no manual API key entry. The npm global install manages the binary and browser auth links to your existing Claude account. Total setup time: approximately three minutes.

the aha moment

The First "Aha" Moment

On day three, I had a disorganized authentication module — error handling scattered across files, inconsistent naming conventions, two functions that did nearly the same thing. In the browser, I would have copied one file at a time, requested suggestions, and manually applied them.

With Claude Code, I just described the problem:

prompt
The auth module under src/auth is inconsistent.
Error handling is spread across 4 files with different
patterns. Unify it — pick the cleanest approach already
in the codebase and apply it everywhere.

Claude analyzed the files, identified the dominant pattern, proposed a plan, and — after my approval — edited all six affected files. I ran /diff to review every change before accepting. The whole thing took about 90 seconds. That same task, done manually, would have been 45 minutes of careful, error-prone editing.

"The shift isn't 'AI writes my code.' It's 'I describe outcomes, Claude handles the execution, I review the result.'"

commands

Essential Commands I Used Daily

There are over 60 built-in commands. These are the five I opened every session with:

  • /diff — Shows every file Claude modified this session. Use as a checkpoint before moving on. Non-negotiable.
  • /clear — Completely fresh context. Use this when switching to a genuinely new, unrelated task.
  • /compact — Compresses conversation history when a session runs long. Run proactively — not after you notice slowdown.
  • /memory — Shows what Claude has inferred about your project on its own. Read this before writing CLAUDE.md — don't duplicate what it already knows.
  • /help — Lists all available commands. Type / and browse the full list at least once.
claude.md

CLAUDE.md — A Resource I Wish I'd Known About Earlier

Each session starts with a blank context window. By day three, I was tired of re-explaining my project — the tech stack, naming conventions, which commands to run. There had to be a better way.

CLAUDE.md is a markdown file in your project root. Claude reads it automatically at the start of every session — a permanent briefing document. Here's the format that worked for me:

markdown
# My Project
## Stack
- Node.js 20, Express, PostgreSQL
- React 18 on the frontend
- Docker for local dev
## Commands
- `npm run dev`      — start local server
- `npm test`         — run test suite
- `npm run lint:fix` — fix lint errors
## Conventions
- camelCase for variables, PascalCase for components
- Errors must always be logged before being thrown
- No default exports
## Architecture
- @docs/architecture.md
- @docs/api-standards.md

The @filename syntax is particularly powerful — Claude imports the content of those files directly. Your existing documentation becomes part of Claude's context. After adding this file, sessions transformed: Claude stopped making assumptions and started working effectively from the first message.

💡 Pro Tip

Run /memory before drafting your CLAUDE.md. Claude may have already inferred several things about your project automatically. Only add information it doesn't already know — keep the file lean.

bonus

Bonus: Teaching Claude About Yourself

Switching from ChatGPT after years of use felt like starting from scratch. GPT had accumulated context about my coding style, my preferences, how I ask questions. I was worried about losing that rapport.

Claude's memory system works differently — it's intentional and transparent. You control what it knows. Here's how I rebuilt that context from zero:

Step 1 — Export Your ChatGPT History (optional)

Navigate to Settings → Data Controls → Export data. You'll get a zip with conversations.json. Skim it for conversations where you articulated your preferences, stack, or working style. Extract those details — don't paste the whole thing.

Step 2 — Enable Claude's Memory

Go to Claude Settings → Memory and activate "Generate memory from chat history." Claude will automatically extract facts about you during conversations — your role, preferences, recurring patterns — and persist them across sessions. You can view, edit, or delete any memory entry at any time.

Step 3 — Write Your Personal Context Prompt

Don't wait for Claude to infer everything. Give it a head start by pasting something like this into a new conversation:

prompt
Here's context about me — please remember this:
## Who I am
- Role: fullstack developer, 5 years experience
- Location / timezone: Hanoi, GMT+7
- Current focus: learning Claude Code, building side projects
## How I like to work with AI
- Prefer direct answers over long explanations
- Show code first, explain after if needed
- I learn by doing, not by reading theory
- Casual tone is fine — no need to be formal
## My tech stack
- Daily: Node.js, React, PostgreSQL
- Exploring: agentic AI tools, Claude Code workflows
## Things I dislike
- Bullet-point overload when prose would do
- Re-explaining basics I already know
- Overly cautious hedging on technical questions

Step 4 — Set User Preferences in Settings

Navigate to Settings → User preferences and write a short paragraph there. This is loaded into every conversation as a baseline — before you type anything. Standing instructions.

Step 5 — Add a Personal Section to Your Global CLAUDE.md

For Claude Code specifically, there's a global memory file at ~/.claude/CLAUDE.md — not inside any project, but accessible across all of them:

markdown
## About me
- Fullstack dev, prefer Node/React
- Casual communication style, direct feedback welcome
- I review all diffs before accepting — don't rush to summarize
- Vietnamese is my first language; English technical terms are fine
✓ Key Difference from GPT

Claude's memory is visible and editable. If it learns something incorrect about you, you can correct it directly. That's fundamentally better than an opaque model quietly building a profile you can't inspect or modify.

friction

Honest Friction Points

The experience wasn't entirely seamless. Three things caught me out:

Context degradation is real. During long sessions, Claude can lose track of earlier decisions. Run /compact proactively — before you notice a decline, not after. I learned this the hard way after a two-hour session where Claude forgot a constraint I had set at the start.

Prompting is a skill. A vague request like "Fix the bug" produces mediocre results. Goal-oriented prompts with clear constraints consistently outperform ambiguous ones:

❌ Vague prompt
"Fix the bug"
"Clean up the auth module"
"Make the tests pass"
✅ Goal-oriented prompt
"Login returns 200 on invalid credentials — trace it, find the root cause, fix it without changing the function signature"
"Unify error handling across src/auth — apply the pattern already used in auth.service.ts"
"The UserRepository test is failing on line 42 — read the test, understand what it expects, then fix the implementation"

Always review before accepting. Claude may confidently propose changes that are subtly off — not broken, but not quite right. /diff is your safety net. Use it at the end of every session.

✓ End of Week Verdict

Claude Code has genuinely changed my workflow. Not because it's magical — because it eliminates the most tedious parts of the edit-test-review cycle. The learning curve is real but short. By day five, it felt completely natural.
